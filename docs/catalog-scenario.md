# 馆藏日期字段批量筛查：可复现场景

本场景模拟馆藏/书目元数据导入时对 EDTF 日期字段的质量检查与检索预筛。
语法写法取自美国国会图书馆的
[EDTF 规范](https://www.loc.gov/standards/datetime/)及
[RDA 日期指导](https://www.loc.gov/aba/rda/mgd/timespan/mg-timespan.pdf)；
`R-01` 等 ID 和六条记录组成的批次是**明确标注的示范输入**，并非下载的真实馆藏记录。

## 输入与验收边界

查询窗为 `1985-04-01` 到 `1985-04-30`，首尾都包含。六条示范日期字段为：

| ID | 输入 | 预期 |
| --- | --- | --- |
| R-01 | `1985-04-XX` | 窗口内；不补成 4 月 1 日 |
| R-02 | `1985-XX-XX` | 可能重叠；其外包络覆盖整年 |
| R-03 | `1984?` | 人工复核；不确定性没有可证明的数值边界 |
| R-04 | `1984-02-30` | 格式错误 `INVALID_DAY`，偏移 7 |
| R-05 | `2004-XX` | 窗口外 |
| R-06 | `[1666,1667]` | 窗口外；仍保留“择一”语义 |

输出计数应为 `invalid=1 review=1 outside=2 within=1 possible=1`，
且每条输入都有一条结果。四目标的同一输出由 CI 运行并由测试块断言。

```sh
moon run examples/catalog-audit --target js
moon test --target js --deny-warn
```

`Outside` 与 `Within` 仅针对保守外包络；`PossibleOverlap` 可以是假阳性，例如
`[1984,2004]` 对 1990 年窗口会得到可能重叠，因为外包络含 1990，实际两个候选却
都不在窗口内。项目不会把这个结果冒称确定命中。季节、近似日期、未知/开放端点及
日期时间一律不自动推算；导入方仍需人工核对或使用更完整的上层业务规则。
