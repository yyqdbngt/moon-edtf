# Moon EDTF 项目申报书（参考稿）

## 一、项目名称和仓库地址

- 项目名称：Moon EDTF——面向不完整时间数据的校验、检索与关系分析工具
- GitHub 仓库：https://github.com/yyqdbngt/moon-edtf
- MoonBit 包：`yyqdbngt/moon_edtf`
- 开源许可证：Apache-2.0

## 二、项目简介

现实系统中的时间字段不总是精确时间戳。科研观测可能只知道月份，项目资料可能只
记录年份，历史事件可能标记为“不确定”，业务记录还会出现开放区间、未知端点和非法
日期。若应用直接把这些值补成某月 1 日或某年 1 月 1 日，会制造并不存在的精度，进而
造成错误排序、错误筛选和错误统计。

Moon EDTF 是一个纯 MoonBit 的通用时间数据质量与查询组件。项目解析一个边界明确的
EDTF 子集，保留精度、不确定性、近似、掩码、区间与集合语义；在此基础上提供批量诊断、
保守时间包络、时间窗筛选、跨记录关系判断和通用数据集审计。项目不绑定档案或馆藏，
调用方只需提供记录 ID、业务分类和时间字符串，即可用于科研数据、事件索引、产品有效期、
项目里程碑、知识图谱和元数据治理。

## 三、项目方向与适用场景

项目属于 MoonBit 生态中的数据质量与时间处理基础库，适合以下可复用场景：

1. **科研和物联网数据治理：** 校验观测日期，区分精确日、仅知月份、仅知年份和不确定值；
   查询某一时间窗内的观测，同时保留需要人工确认的数据。
2. **事件检索与 API 过滤：** 后端可选择“仅返回确定落入时间窗的记录”或“同时返回可能
   相交的候选记录”，避免用同一种策略处理精确搜索和召回优先搜索。
3. **业务有效期与项目管理：** 对合同、产品版本、项目阶段等时间区间执行先后、包含、
   被包含和可能相交判断，用于冲突检查与时间关联。
4. **知识图谱、档案与开放数据清洗：** 批量输出规范化值、稳定错误码和原字符串偏移；
   对无法安全计算边界的记录进入人工复核，而不是静默补齐日期。

## 四、核心功能

1. 解析精确/部分日期、长年份、季节、不确定与近似标记、掩码月日、日期时间、闭合及
   开放/未知区间、择一集合和全部成员集合。
2. `diagnose` / `diagnose_batch` 对单条或批量输入返回稳定错误码、UTF-16 错误偏移和
   规范化结果，调用方无需用异常控制整个批次。
3. `date_envelope` 在能够证明时计算保守的最早/最晚日期；不确定值、开放区间和季节等
   无法可靠计算的输入会明确拒绝，不编造边界。
4. `query_temporal_records` 对任意业务记录执行通用时间窗审计，保证每个输入都有结果；
   输出 invalid、needs-review、outside、within、possible-overlap 五类结论、选中 ID 和
   数据集安全覆盖范围。
5. `MatchPolicy::WithinOnly` 与 `IncludePossibleOverlap` 分别支持精确导出和召回优先检索。
6. `temporal_relation` 判断两条记录的确定先后、相同覆盖、包含、被包含或可能重叠，
   可用于时间关联和冲突检查。
7. 保留原有 `audit_catalog` API，旧版馆藏场景可继续使用，新版通用 API 不依赖业务域。

## 五、实际场景测试与验收结果

仓库提供 `examples/temporal-query` 可运行场景，输入五条来自不同业务类别的示范记录：
精确科研观测日 `2024-05-18`、产品年份 `2024-XX`、项目区间 `2022/2023`、不确定事件
`2024?` 和非法 API 日期 `2024-02-30`。查询 2024 年 5 月并采用召回优先策略，验收结果为：

- 确定在窗内 1 条；可能相交 1 条；窗外 1 条；人工复核 1 条；非法 1 条；
- 自动选中前两条，未把不确定值和非法值混入结果；
- 非法日期返回 `INVALID_DAY`，错误偏移为 7；
- wasm、wasm-gc、js、native 四后端应输出相同分类结果。

测试还构造 10,000 条混合业务记录，断言输入与输出均为 10,000 条，五种结论各 2,000
条，召回优先策略选中 4,000 条，从而验证批量路径不会丢记录且计数稳定。关系测试覆盖
先后、相同覆盖、包含、被包含、可能重叠，以及对不确定和无界值的拒绝行为。详细复现步骤
见 `docs/temporal-query-scenario.md`。

## 六、技术路线与工程质量

项目使用 UTF-16 游标解析器构建类型化 AST，将语法解析、日期校验、规范化、保守包络、
查询策略和批量报告分层实现。错误类型只携带稳定代码和偏移，不回显输入，便于上层安全
记录。当前根目录生产 MoonBit 源码约 1,534 行 / 7 文件，测试约 673 行 / 6 文件，
共 44 个测试块；示例和文档不计入上述源码统计。GitHub Actions 在四个 MoonBit 后端
执行格式检查、静态检查、构建、全部测试及三个示例，减少单后端偶然通过的风险。

## 七、验收边界

本项目当前交付边界是“保留语义的结构化时间校验与保守查询”，不宣称完整 EDTF 等级
兼容，不做自然语言日期识别、时区换算、闰秒、日期枚举或不确定性概率推断。外包络的
`possible-overlap` 只表示候选相交，可能是假阳性；需要确定性结果时应使用
`WithinOnly`。日期时间当前可解析和规范化，但不参与日级包络计算。上述限制均由文档和
错误码明确暴露。

## 八、原创性、生态差异与后续计划

项目为独立的 MoonBit 实现，参考 Library of Congress 发布的 EDTF 规范资料，未移植
第三方解析器。普通日期库通常面向精确时间戳计算；本项目的差异是保留不完整和不确定
时间的语义，并在无法证明时拒绝自动判断。后续计划包括可插拔 JSON/CSV 适配示例、
流式批处理、更多 EDTF 语法、可复现性能基准及与数据库查询层的集成，但这些计划不计入
当前已完成成果。
